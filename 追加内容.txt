配置字段级别加密
上次更新时间: 2025-02-13
您可以对 IBM OpenPages® 存储库中的特定字段进行加密，以防止系统管理员直接从数据库查看机密数据。 加密字段中的数据显示为随机字符字符串。

支持简单字符串和长字符串字段数据类型。

已加密的字段不适合在全局搜索中使用。
注: 在 Oracle 12.2上运行的 OpenPages 中加密长字符串之前，请参阅以下技术说明: http://www.ibm.com/support/docview.wss?uid=swg22010106。 该技术说明描述了潜在问题，以及如何通过从 Oracle 支持获取相应的补丁并将其应用于您的环境来解决该问题。 IBM OpenPages 报告框架通过运行数据库函数对已加密的字段进行解密来处理这些字段。 当对长字符串 (CLOB) 字段进行加密时，必须重新生成框架以调用此数据库函数。 有关更多信息，请参阅 生成报告框架。

限制：

    可加密的长字符串的最大大小为 2 MB。
    请勿在过滤器的搜索条件中包含加密的长字符串字段，因为这些字段可能会返回意外结果。

您需要执行以下任务以使用字段级别加密:

    创建包含加密密钥库和密钥对的文件。 请参阅 创建加密密钥库文件和密钥对。
    设置加密密钥库。 设置加密密钥库
    将密钥库文件放在环境中的应用程序服务器上。
    在水平环境中，密钥库文件必须可供每个应用程序服务器使用。 有两个选项：
        每个应用程序服务器都必须有权访问管理应用程序服务器上的文件位置。
        该文件必须在每个应用程序服务器上的相同位置中可用。

    在非集群环境中，将密钥库文件放在管理应用程序服务器上。
    启用密钥库。 请参阅 启用加密密钥库。

注: 如果已配置字段级别加密，但密钥的属性已更改，请参阅 更新加密密钥库。

    启用加密密钥库
    设置加密密钥库后，必须使其能够对 IBM OpenPages 存储库进行加密。 如果需要，您可以稍后禁用密钥库以再次解密存储库。
    禁用加密密钥库
    在对 IBM OpenPages 存储库进行加密之后，您可以禁用密钥库以再次对存储库进行解密。

加密服务器变量
上次更新时间: 2025-02-13

适用于： 在本地 在云端

您可以在管理应用程序服务器上使用环境变量来配置用于AES加密的密码模式，并启用或禁用 3DES 加密的初始向量（IV）的随机化。 这些设置会影响字段级加密和属性文件中的密码加密。
默认情况下， 9.0.0.5 和更高版本中，AES的加密模式为Galois Counter Mode（ GCM ）， 3DES 初始化向量是随机的。 现有的加密值仍然可用，但所有新的加密过程都使用 GCM。

    如果您想使用默认设置，则无需任何操作。
    如果您需要使用之前的默认模式——密码块链接（CBC），请在 server.env 文件中设置环境变量。
    如果您想将Counter与密码块链接消息认证（CCM）结合使用，请在 server.env 文件中设置环境变量。

server.env 文件的位置是： <OP_HOME>/wlp-usr/servers/opapp-<server_name><#>/server.env

aes.encryption.transformation
    使用此变量指定用于AES加密的密码模式。
    可以使用以下值：

        AES/GCM/NoPadding：将密码模式设置为伽罗瓦计数模式（ GCM ）。
        AES/CCM/NoPadding：将密码模式设置为“带密码块链接的消息认证（CCM）”的“计数器”。
        AES/CBC/PKCS5Padding （这是传统设置。）

    缺省值：AES/GCM/NoPadding
3des.encryption.randomiv
    使用此变量可启用 3DES 初始化向量的随机化。
    请使用默认值，除非您正在管理一个需要非随机IV的旧系统。

        true：启用随机IV进行加密。
        false：保留旧版行为，以便与旧版系统兼容。

    缺省值：true

注意： 添加或修改这些变量后，请重启应用服务器以应用更改。
示例

要使用 GCM 模式和随机的 3DES 初始化向量，无需任何操作。
要将默认的 GCM 模式更改为CBC模式，请在 server.env 文件中添加以下几行：

aes.encryption.transformation=AES/CBC/PKCS5Padding
3des.encryption.randomiv=true

要将 GCM 模式更改为CCM模式，请在 server.env 文件中添加以下几行：

aes.encryption.transformation=AES/CCM/NoPadding
3des.encryption.randomiv=true

LDAP 用户认证
上次更新时间: 2025-02-13

IBM OpenPages® 支持使用 LDAP (轻量级目录访问协议) 认证服务器来控制用户访问权。

要使用 LDAP 用户认证，请将 OpenPages 与 LDAP 数据源集成。

只能同时有一个登录模块处于活动状态。 OpenPages 支持单个名称空间。 所有用户都必须通过同一数据源进行认证。 可在多森林环境中使用多个认证模块。

还必须在 LDAP 认证服务器中定义创建或导入到 OpenPages 中的用户。 管理 OpenPages 用户的管理员负责维护 OpenPages 用户列表与外部 LDAP 数据源之间的关联。 如果在 OpenPages 服务器上禁用了用户，那么必须在 LDAP 目录服务器上手动禁用该用户。
注: 如果 LDAP 目录服务器用于用户认证，那么将在 OpenPages中禁用 更改密码 选项。 使用 LDAP 服务器时，不会在 OpenPages中维护密码。 必须在 LDAP 服务器中更改密码。

您还可以配置 OpenPages 以通过 SSL 使用外部 LDAP 用户认证服务器。 有关更多信息，请参阅 修改 LDAP over TLS 的 LDAP 配置文件。

    配置 LDAP 认证模块
    要成功将 LDAP 目录服务器与 IBM OpenPages配合使用，必须配置 LDAP 认证模块以识别 LDAP 服务器的存在。
    设置混合方式认证
    当并非所有用户都可以使用单个名称空间进行认证时，使用混合方式认证。
    配置多森林 LDAP 认证
    IBM OpenPages 支持在多森林配置中使用多个 LDAP 认证服务器。 如果应用程序在第一个认证服务器中找不到用户，那么它将检查列表中的下一个服务器并重复，直到它找到该用户或检查所有列出的认证服务器为止。

修改 LDAP 配置文件
上次更新时间: 2025-02-13

您必须修改认证配置文件以启用您正在使用的 LDAP 目录服务器。
注: 如果使用 LDAP over SSL ，请参阅 修改 LDAP over TLS 的 LDAP 配置文件。

aurora_auth.config 文件包含三个认证模块:

    Openpages -缺省内部用户目录
    OpenpagesIP -Sun One Directory Server 的样本 LDAP 配置
    OpenpagesAD -Microsoft Active Directory Server 的样本 LDAP 配置

IBM OpenPages® 系统关注的唯一模块是名为 Openpages的模块。 因此，您需要备份 Openpages 模块，将 OpenpagesIP 或 OpenpagesAD 重命名为 Openpages，然后更改设置以反映 LDAP 服务器的设置。
过程

    停止所有 OpenPages 服务。
    在文本编辑器中打开并编辑 <OP_Home>/aurora/conf/aurora_auth.config 文件。

    其中：


                         <OP_Home>
                      是 OpenPages 应用程序的安装位置。
    查找 Openpages 模块并将其名称更改为 OpenpagesDefault。
    将 OpenpagesIP 或 OpenpagesAD 模块名称修改为 Openpages。
        如果您正在使用 Microsoft Active Directory 服务器，请将 OpenpagesAD 模块的名称更改为 Openpages。
        如果要使用 Sun One Directory Server ，请将 OpenpagesIP 模块的名称更改为 Openpages。
        如果您正在使用其他 LDAP 服务器，那么可以使用其中任一模块。 选择要用作模板的模块，并将其名称更改为 Openpages。
    在名为 Openpages的模块中为以下属性指定正确的值:

    provider.url
        将该值更改为 LDAP 认证服务器的主机名和端口号。 对于 LDAP ，协议为 ldap ，端口为 LDAP 端口号 (缺省情况下为 389)。
    base.dn
        LDAP 服务器上 LDAP 目录树结构（域名）的顶级。 如果要认证的用户位于 Active Directory 结构中的多个位置，请使用位置的专有名称显式列出所有位置，每个位置以分号分隔。
        例如：


        base.dn="DC=LDAPTesting,DC=local;CN=Users,DC=LDAPTesting,DC=local;
        OU=Auditors,OU=External Auditors,OU=Staff,DC=LDAPTesting,DC=local"

    user.attr.id
        用户标识的属性名称 (例如， uid， cn等)
    其他定制参数
        您可以添加 Java™ 命名和目录接口 (JNDI) 支持的其他定制参数。 在 JNDI 属性之前添加 ctx.env. 前缀。

        例如，如果要使用 JNDI 属性 com.sun.jndi.ldap.connect.timeout，请在 aurora_auth.config 文件中使用 ctx.env.com.sun.jndi.ldap.connect.timeout="<value>" 。

        有关 JNDI 属性的信息，请参阅 Java SE 文档 (http://docs.oracle.com/javase/7/docs/technotes/guides/jndi/jndi-ldap.html#JNDIPROPS)。

    例如：

    Openpages
    {
       com.openpages.aurora.service.security.namespace.LDAPLoginModule 
              required debug=false
          provider.url="ldap://myserver.company.com:389"
          security.authentication="simple"
          security.search.user.dn="cn=Directory Manager"
          security.search.user.credentials="openpages"
          base.dn="ou=people,o=IBM,c=US"
          user.attr.id="uid"
          ;
    };

    完成编辑文件后，保存更改并退出。
    重新启动所有服务。

结果

您已将 OpenPages 系统配置为使用外部 LDAP 用户认证服务器。

设置混合方式认证
上次更新时间: 2025-02-13

当并非所有用户都可以使用单个名称空间进行认证时，请使用混合方式认证。

此解决方案适用于那些不想在LDAP服务器上创建OPSystem、SOXAdministrator OpenPagesAdministrator, 或OPAdministrator用户账户，但希望所有用户都通过LDAP认证的客户。 以下过程将创建新的名称空间并修改用户名 (例如， OPSystem) 以针对 OpenPages® 认证模块而不是 LDAP 进行认证。
过程

    要在 aurora_auth.config 文件中创建名称空间模块，请登录到应用程序服务器。
    查找并打开 aurora_auth.config 文件。
    创建或更新文件中的名称空间模块，如下所示:

    OpenpagesDefault
    {
    com.openpages.aurora.service.security.namespace.AuroraLoginModule
    required debug=false;
    };


    Openpages
    {
    com.openpages.aurora.service.security.namespace.LDAPLoginModule required 
    debug=false 
    provider.url="ldap://192.168.0.169:30429" 
    security.authentication="simple"
    base.dn="DC=LDAPTesting,DC=local;OU=People,DC=LDAPTesting,DC=local"
    user.attr.id="uid"
    ;
    };

    要在数据库中创建名称空间，请使用数据库标识 (例如 OPENPAGES) 登录到数据库实例。
    运行以下 SQL 以创建 OpenpagesDefault 名称空间:

    insert into namespaces (NAMESPACEID, NAME, JAASLOGINMODULE,
    DESCRIPTION) values (namespaceidseq.nextval, 'Openpages Security',
    'OpenpagesDefault', 'Default Openpages Security Namespace');

    运行以下 SQL 以将标识指向新的名称空间:

    update actors set namespaceid = (select namespaceid from 
    namespaces where JAASLOGINMODULE = 'OpenpagesDefault') where actorid = 
    (select actorid from actorinfo where name = 'user_name');

    例如，以下 SQL 将使 OPSystem 使用 OpenpagesDefault 名称空间进行认证:

    update actors set namespaceid = (select namespaceid from
    namespaces where JAASLOGINMODULE = 'OpenpagesDefault') where actorid =
    (select actorid from actorinfo where name = 'OPSystem');

    将更改落实到数据库。

配置多森林 LDAP 认证
上次更新时间: 2025-02-13

IBM OpenPages® 支持在多森林配置中使用多个 LDAP 认证服务器。 如果应用程序在第一个认证服务器中找不到用户，那么它将检查列表中的下一个服务器并重复，直到它找到该用户或检查所有列出的认证服务器为止。

列示多个 LDAP 服务器时，必须修改 aurora_auth.config 文件以包含多组服务器信息。

此文件位于 <OP_Home>\aurora\conf 目录中，其中 
            <OP_Home>
         是 OpenPages 应用程序的安装位置。 缺省情况下为 c:\OpenPages。

通过按索引键对服务器信息进行分组来完成此操作，如以下示例中所示:


com.openpages.aurora.service.security.namespace.LDAPLoginModule required 
debug=true
provider.url.1="ldap://10.128.22.106:389"
security.authentication.1="simple"
security.search.user.dn.1="CN=Administrator,CN=Users,DC=parent,DC=parentchil
d,DC=localdomain" 
security.search.user.credentials.1="Op3nPag3s"          
base.dn.1="DC=parent,DC=parentchild,DC=localdomain"
user.attr.id.1="CN" 
provider.url.2="ldap://10.128.22.107:389"
security.authentication.2="simple"
security.search.user.dn.2="CN=Administrator,CN=Users,DC=child,DC=parent,DC=p
arentchild,DC=localdomain" 
security.search.user.credentials.2="Op3nPag3s"          
base.dn.2="DC=child,DC=parent,DC=parentchild,DC=localdomain"
user.attr.id.2="CN" 

通过将 ".1" 键添加到每个参数的末尾， OpenPages 可以正确解析设置并区分单独的 LDAP 服务器信息集。 将 ".2" 附加到第二个 LDAP 服务器的密钥，依此类推。

对于单个 LDAP 服务器实现，您不需要将标识附加到参数名称的末尾。
